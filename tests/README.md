# Project2 / Project3 Tomasulo+ROB Tests

Supported instructions: `add`, `addi`, `mul`, `lw`, `sw`, `beq`, `nop`
Stop condition: store to address `100` triggers `FINAL_SIGNATURE` and stops simulation.

## Baseline Tests (pre-ROB, still valid)

- `tomasulo01_addi_smoke.s`    → expected `5`   — ADDI + SW smoke test
- `tomasulo02_add_chain.s`     → expected `21`  — ADD/ADDI chain with data dep
- `tomasulo03_mul_basic.s`     → expected `42`  — MUL basic
- `tomasulo04_sw_lw_roundtrip.s` → expected `33` — SW then LW from same address
- `tomasulo05_dual_independent.s` → expected `11` — 2 independent ADDIs dispatched together
- `tomasulo06_slot_dep.s`      → expected `9`   — slot0→slot1 same-cycle RAW forwarding
- `tomasulo07_mul_add_mix.s`   → expected `17`  — MUL and ADD execute in parallel (OOO)

## ROB-Specific Tests (Project3)

- `rob01_waw_order.s`     → expected `99`  — WAW: MUL then ADDI to same reg; ADDI (fast) executes first but must commit second; rename ensures ADDI value (99) reaches the store, not MUL value (42)
- `rob02_beq_not_taken.s` → expected `43`  — BEQ with false condition (5≠3); predict-not-taken is correct; no flush; instruction after branch executes normally
- `rob03_beq_taken.s`     → expected `77`  — BEQ with true condition (7=7); predict-not-taken is wrong; ROB commits branch, detects misprediction, flushes speculative state, redirects fetch; architectural x10=77 survives the flush

Each `.s` file has a matching `.mem` generated by `asygen.py`.

## ModelSim Run (Primary)

```bash
./tests/run_tomasulo_modelsim.sh tests/tomasulo01_addi_smoke.mem tomasulo01_addi_smoke
```

The runner compares `FINAL_SIGNATURE` against the expected value for known Tomasulo tests.

Optional third argument overrides the expected value:

```bash
./tests/run_tomasulo_modelsim.sh tests/tomasulo01_addi_smoke.mem tomasulo01_addi_smoke 5
```

You can now also use named options:

```bash
./tests/run_tomasulo_modelsim.sh \
	--mem tests/tomasulo03_mul_basic.mem \
	--test tomasulo03_mul_basic \
	--maxcyc 4000 \
	--dbg 1
```

### Passing "Other Vsim Options"

Anything after `--` is forwarded directly to `vsim`.

```bash
./tests/run_tomasulo_modelsim.sh \
	--mem tests/tomasulo03_mul_basic.mem \
	--test tomasulo03_mul_basic \
	-- -voptargs=+acc -wlf waves.wlf
```

You can also use env var `VSIM_EXTRA_OPTS` for extra options:

```bash
VSIM_EXTRA_OPTS="-voptargs=+acc -wlf waves.wlf" \
./tests/run_tomasulo_modelsim.sh --test tomasulo03_mul_basic
```

### Run in ModelSim UI

Use `--gui` to launch UI mode instead of `-c`:

```bash
./tests/run_tomasulo_modelsim.sh --test tomasulo01_addi_smoke --gui
```

In GUI mode, the simulation does not auto-run by default; you can click Run in the UI or pass a custom `-do` script through the forwarded options.

```bash
./tests/run_tomasulo_modelsim.sh --test tomasulo01_addi_smoke --gui -- -do "run 2000ns"
```

Run the full project-specific test set:

```bash
./tests/run_tomasulo_modelsim_suite.sh
```

Suite options are forwarded to every test, for example:

```bash
./tests/run_tomasulo_modelsim_suite.sh --maxcyc 5000 -- -voptargs=+acc
```
